A 3D-gomb transformját négy rendszer animálja egyszerre, és még 41 transition: all maradt

MiA Lakitelek „3D modell betöltése” gombon egy végtelen CSS pulse (scale 1→1,05), egy CSS :hover { transform: scale(1.1) }, egy túllövő transition: all 0.4s cubic-bezier(.175,.885,.32,1.275) és a Framer whileHover={{ scale: 1.1 }} versenyez ugyanazért a transform-ért. A CSS-animáció felülírja a Framer inline stílusát, így hover alatt a gomb a kettő között ugrál. A CLAUDE.md kifejezetten tiltja a transition: all-t Framer-elemen. Az élő kódban még 41 ilyen sor van (a halott BookLayout nélkül), köztük a fejlécen és a szekciósínen.

Miért számítEz a 3D-diagram egyetlen belépési pontja. Ha a hover rángat, az olcsónak hat, pont ott, ahol a legértékesebb tartalom kezdődik. A transition: all ráadásul olyan tulajdonságokat is animál (padding, width, box-shadow), amelyeket senki nem szánt animálni.

Javasolt mozgásEgy gazda: a transform a Frameré (whileHover helyett csak whileTap={{ scale: 0.97 }}), a CSS csak a background, border-color és box-shadow tulajdonságot animálja, 160 ms ease-out alatt. A pulzálás törölhető, a gomb a felirattal együtt elég hívogató. A többi transition: all sort érdemes egy körben explicit tulajdonságlistára cserélni.
